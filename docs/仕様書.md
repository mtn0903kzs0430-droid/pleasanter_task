# タスク管理・作業時間集計サンプル 仕様書

## 目的

プリザンターで日次の予定と作業実績を記録し、Excelで確認・調整して請求書と業務内容報告書を作成する個人利用向けサンプル。

## プリザンター

| サイト | 役割 |
|---|---|
| 取引先マスタ | 作業の取引先を管理 |
| タスク管理 | 予定・内容・状況・実績日時・休憩・作業時間・集計対象を管理 |
| 定例タスクマスタ | 開始時刻、所要時間、曜日、有効期間を指定するひな型 |

主な追加機能：

- 今日の日表示：ビュー「カレンダーtoday」とCL_3。対象ビューIDの一致が必要。
- 選択タスクの一括コピー：CL-02 タスク生成コマンド、SS-01 タスク生成コマンド。タイトル・内容などを引き継ぎ、実績等を初期化。一度に50件まで。
- 本日の定例作成：同じCL-02とSS-01を使用。有効ON、適用期間内、指定曜日に該当するマスタから作成。曜日空欄は毎日、期間の各端点が空欄ならその側の制限なし。生成キーで当日分の重複を確認。有効マスタは50件まで。
- 一覧の計測：分類D「計測」、SS-03 一覧の計測ボタン、CL-04 一覧から開始・終了、SS-04 一覧計測の更新検証、スタイル「計測ボタン（一覧・編集）」、プロセス1・4を使用。開始前→実施中→完了と実績日時を記録。中断・再開は詳細画面で操作。

定例作成の参照先ID、分類のリンク先、ビューIDは、インポート先と照合する。旧プロセス「一括コピー」と旧SS-01 一括コピーは既存の4サイト版では無効。

## Excel v1.2

Windows版Excelのマクロ有効ブック。シートは操作・集計、取得データ、請求書、業務内容報告書。1回に1社の帳票を作成する。

### 接続設定

- VBAのAPI_BASE：接続先。初期値localhostはExcelを動かすPC。
- VBAのCLIENT_SITE_ID：取引先マスタのサイトID。
- 操作・集計C3：タスク管理のサイトID。
- C7：取引先レコードID。サイトIDとは異なる。
- Windowsユーザー環境変数PLEASANTER_API_KEYからAPIキーを取得。Excel再起動が必要。未設定なら通信前に停止。環境変数は暗号化保管庫ではない。

### 操作・データ

1. C4に取得開始日を入力。現在の利用者編集版ではC5のEOMONTH式で月末を設定。
2. データ取得：指定サイト・取引先・実績開始期間・集計対象ONで取得。ページングあり。取得成功時に全明細を入れ替え、前回の調整時間・メモをクリア。正常0件なら明細は空。取得失敗時は既存データを保持する設計。
3. 取得データG列に調整後の時間、H列に内部メモを入力。I列はG空欄ならF、G入力時はGを使う式。0と空欄を区別。時間単位は十進数h。
4. 帳票作成：対象1社の明細を報告書へ値転記。備考は空欄で作成し、調整メモは転記しない。数量は調整後時間の合計。再作成すると報告書の手修正は置き換わる。
5. PDF出力：現在の2帳票を別PDFに出力。帳票は再作成しない。同名は連番で保存。メール送信なし。

請求日・入金期日は、帳票の対象期間が変わる際に初期設定。同じ期間では保持。報告書作成日は帳票作成日。取得反映前・帳票作成前にバックアップを保存する。

## 導入・検証の境界

JSONの出力情報は1.5.2.0。公開用一式の新規環境へのインポート・Excel接続の通し確認は未実施。既存4サイト版JSONのタスク管理ID9974と、Excel初期設定9664は一致しないため、そのまま接続できるセットではない。

Excelの過去検証は架空API応答とPDF出力等。利用者編集後のコメント・色については読み取り点検済みだが、埋め込みVBAと外部ソースの同一性、編集後の実行再確認は未完了。公開前に確認する。

中断日時は1組であり、複数回中断の累計が実装済みとは扱わない。個別の請求契約・丸め方法に合わせて確認して使う。
